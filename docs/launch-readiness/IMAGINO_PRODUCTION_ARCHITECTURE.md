Future isolation: dedicated production Render web service/profile; separate Mongo database/project/cluster and restore destination; private output/input R2 buckets without public r2.dev/custom-domain/Worker routes; distinct least-privilege provider keys; separate Google/Resend/Stripe live configuration; Vercel production environment and approved domains. Never copy staging credentials. Keep all providers/checkout off until gates pass.
Initial architecture proposal: one API and one logical worker admission stream; durable Mongo leases/transactional budgets. In-process single-job worker suffices for controlled staging; paid production needs an always-running approved tier and capacity evidence. Separate worker when sustained backlog, long video polling, API memory impact or scaling exceeds one stream. Shared budgets/leases remain mandatory; scale only after OAuth/proxy/lease tests. No plan upgrade purchased.

Capacity estimates, not approvals: start waitlist/manual admission, one image plus at most one video in flight per operational stream; review user/video limits and provider caps independently. Worker provider operation timeout is two minutes, lease five minutes; lease timing/restart/known-task recovery must be rechecked under actual CPU/network tier.
Historical costs supplied by prior phase, not measured again: BFL klein 0.014 USD, Pro 0.030, reference Pro 0.045, Flare 0.01340, five-second video 0.160. At 100 images/10 videos using these examples: about 3–6.1 USD provider output cost before retries/tokens/tax/storage/overheads; do not use as a hard ceiling. Required budget uses approved complete-request maximum. If observed service time is T seconds, one serial worker upper bound is 3,600/T jobs/hour before polling/network/storage; measure T before choosing users.
Storage growth formula: completed images × measured mean bytes + videos × measured mean bytes + reference retention; do not infer from a few samples. Full buffering can consume multiple times media cap in server/browser; 100 MiB video capacity and Range throughput remain P1 validation.

Read-only Vercel domains observed: imaginoai-app.com; imagino-front.vercel.app; project and master aliases. Proposal root/www landing, app workspace, api under same approved registrable domain; simpler root app is possible. Exact domain choice, TLS, CORS, cookie SameSite, OAuth, email and canonical remain human gate.
